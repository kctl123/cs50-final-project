# Restaurant Recommender
#### Video Demo: https://youtu.be/ePKPC4QKg3I
#### Description:

Restaurant Recommender was created as I found deciding what to eat whenever I went on an outing with my friends or family a hassle. What Restaurant Recommender does is that by inputting a cuisine, region and budget, it recommends you places that fulfil that criteria. I also decided to implement a "You may also like" feature as I always found that feature quite intriguing and I wanted to figure out how to do it. The AI tools I used were ChatGPT and Copilot, the former for breaking down new concepts like how to use API's and how to structure my code whereas the latter was used for its autocomplete function, saving me time when it comes to the boilerplate stuff. 

To start: layout.html, I created a navbar with anchor tags such that the user can click on any of the words and be brought to the respective route

Next would be index.html --> this is the "cover page" of my restaurant and I wanted to beautify it with some icons, which led me to use Flaticon (which I cited in my website as well). I also included some dummy reviews to make the website seem more legit. The hardest part of this section and my takeaways would be the formatting, reading through Bootstrap documentation, deciding which feature of bootstrap to use and so on; the hardest part would be creating the review scroller thing as the cards would be bigger than what I wanted, or the text wouldn't wrap properly and whatnot

Next would be about.html. Similarly, formatting was the biggest issue, but having gone through the pain from index.html, and drawing on some ideas from CS50 finance this part wasn't the worst? 

Following that wokd be register.html, I included client and server side validation such that the user cannot simply disable the required username, password, and security question field. I stored all this data inside a table called users and used wertzkeug security's generate_password_hash function to encrypt the password and not store the raw value of the password itself. What perhaps is notable here would be the password validator, I used javascript to create a dynamic password checker to ensure that the password the user wants to use has to have a capital letter, be at least 8 characters long, has a special character and has a number and whenever the user fulfils the corresponding requirement, that respective line of red text would go away. Only when the user has fulfilled all criteria will they be allowed to register.

Reset.html, as its name suggests, allows the user to reset their password but only if they enter a valid username (ie already have an account) as well as answer their security question correctly. This was done through the UPDATE function of sqlite; after they entered their new password, it would then be rehashed and updated in the database. Afterwards, they would be brought back to login.html to log in 

Regarding login and logout.html, the former is just a standard login page similar to that from CS50 finance, including inserting a user's details into a table to keep track of them as well as their activity (which leads to the history feature) while the latter clears the session and reprompts them to the login page 

For history.html, it was basically storing all of their inputs into a table called preferences which was then displayed using a jinja for loop, limited to the 20 most recent preferences so as to not flood their screen. What was kind of troublesome was that SQL's default timestamp was 8 hours behind my time zone so all the timestamps were off by 8 hours. So naturally, I tried to use ALTER table to drop the current timestamp and use the datetime(now, localtime). However, this gave an error where it could not add a table with a non-constant default. I searched about this problem and realized I had to recreate my whole table, which was quite scary as I did not want to lose my data, giving rise to fix_timestamps.py within my scripts folder, during which I learnt about new SQL commands like conn.rollback() as well as how to transfer data from one table to another

For about.html, I included features of the website, the tech stack, why I created this website as well as a contact me page. The aesthetics and formatting proved to be the biggest challenge (once again) for this route

Moving on to dashboard.html, this was the page that included all the criteria that the user had to fill in before they received their personalized recommendations. Likewise, I ensured server and client side validation to ensure all fields had to be filled in

Up to here, it was still relatively manageable, with the hardest part being having to read and figure out bootstrap documentation. The truly difficult part of this project was having to populate my restaurants table with as many restaurants possible (through an external database) as well as having to assign respective price, region and cuisines for each of the restaurants. 

To begin with, import_ee.py (ee stands for eating establishments); I found a free online database that was free for public use containing eating establishments around Singapore. However, the format for each eating establishment (there were 30000) looked very cryptic on first glance

Needless to say, I was stumped looking at this for the first time. But upon taking a closer look, I realized that I had actually seen some of this in the CS50 lectures before and upon taking a closer look, I realized that this was actually just a nested list -- just that each element within the list also had its own lists and dictionaries, and out of those dictionaries, the key value pair was another dictionary... 
Nontheless, I managed to figure it out (after losing a lot of sanity) with some help from chatgpt and managed to import the data into my table

Next was to assign each restaurant a cuisine through an API, I decided to use Overpass API as it was free and it seemed pretty decent. However, the creators of Overpass created a unique language for Overpass itself and I had to figure out how it worked. But the concepts were kind of similar to what I already knew from CS50's lectures so while figuring it out was pretty bad, it could be worse. This was my first time using an API and to put it simply, I was quite shocked to see it work. Like I could just leave my computer running and it would autopopulate my data? Unfortunately not. What happened was that a lot of my restaurants did not match what Overpass API could find, be it discrepancies in name, location or some other unknown factor. Out of 20000 restaurants (deleted 10000 from the original 30000) only a few hundred matched. Also, given the sheer amount of data, I could not finish populating my entire database within 1 sitting. Only after I finished the first sitting then I realized that this code was flawed as it would run even on restaurants that were already checked. I created a checked column and updated it to be '1' after it was checked and 0 otherwise and in my SELECT query, I would select only those that were '0'. 

Frustrated with the lack of cuisines, I asked chatGPT what workaround there was to this and apparently I could do something called keyword matching, whereby I created a list of words unique to each cuisine and if those words appeared in the restaurant title it would assign that corresponding cuisine, so I did just that and now I had a restaurants table populated with cuisine, location, name and address. 

Moving on to assigning a price to each restaurant, initially, I tried to use an API, however, there were no good free options and I had no choice but to do an approach similar to keyword matching. I matched each cuisine to a certain price range that would fall under either cheap or medium. However, this gave rise to another problem -- a hawker center selling chinese food and a chinese restaurant would naturally be priced differently, similar to how macdonalds would be western food but would be cheaper than a steakhouse, assigning price ranges based purely on cuisine was not enough. 

Hence, I created assign_categories.py that would categorize the food type and the establishment itself, some keywords include Fast food, restaurant, hawker center, food court, cafe and so on. Afterwards, I set the price_range such that food court and hawker centers would be cheap while restaurants, cafe and so on would be medium price

After populating my database, I could finally work on recommend.html which was to return customized restaurants based on the criteria seelcted by the user. I did this through the use of a nested SQL query as I wanted to assign scores to the list of filtered restaurants and return only those that were of a certain score 

To add a finishing touch, I decided to create a "You may also like" feature that takes into account the top 3 cuisines based on the user's preferences and recommending them these cuisines whilst adhering to the region and price_range that they entered in the current preference and not recommending them restaurants that was in the primary recommended list 

To conclude, while this project certainly isn't perfect and there were many many more features I wished to implement but couldn't due to lack of quality data and free datasets, this is a project that I have put my best effort into given whatever resources I had and I genuinely learnt a lot from it. Thank you CS50 for giving me the opportunity to design project that I am proud to call my own.
